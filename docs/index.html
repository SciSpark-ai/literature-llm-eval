SciSpark · evaluation studies

Evaluating large language models in a clinical literature recommender

We built SciSpark and SciSpark Psychiatry to recommend research papers to scientists and psychiatry clinicians, with an LLM at the centre of the pipeline. Here, we test how well the LLM performs at each stage of that pipeline, using public screening data from Cochrane systematic reviews, and we publish everything needed to recompute our numbers.

Study 1 · relevance scoring and evidence attribution

Does asking an LLM to quote its evidence change how it scores relevance?

We found that LLM relevance scores changed for 18% of papers when the identical request was sent again. Asking for a quote in the same call did not clearly change the scores, but lost relevant papers at the quote check; splitting scoring and quoting into two calls recovered evidence for 96–100% of them.

  • 3 topics
  • 100 papers
  • GPT-4.1-mini
  • human relevance labels

LLM or cross-encoder: which ranks a clinical literature feed better?

We found that the LLM placed relevant papers nearer the top than a cross-encoder on all three topics. A cross-encoder helped to order papers that share an LLM score, but cutting the candidate pool with it before the LLM dropped up to 15 of 37 relevant papers.

  • 682 papers

Design implications

Separate scoring from evidence attribution
Score relevance first, then attach evidence in a second call. A paper whose evidence fails the check should be marked unverified, not removed.
Let the LLM point rather than copy
Asking for the number of a supporting sentence, then looking it up in code, gave valid evidence for every kept paper at the lowest cost per verified paper.
Compare prompts over repeated runs
Identical requests at temperature zero changed 18% of scores, so a single run cannot show that one prompt is better than another.
Measure what every filter removes
Quote checks and candidate cut-offs both removed relevant papers, and a top-of-list metric alone did not show it.

How the studies are kept

Hypotheses and pass bars written before the runs · frozen requests and responses · every number recomputable without an API key · limitations stated on each page · no abstracts redistributed.
